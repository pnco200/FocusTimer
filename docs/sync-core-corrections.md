# Sync Core adversarial review corrections

2026-10-17. Follow-up to [the adversarial implementation review](sync-core-implementation-review.md), authorized by the subsequent request to perform the necessary fixes. All six findings F1–F6 have targeted corrections and passing regressions. The original review remains historical evidence; its source line numbers describe the pre-correction snapshot.

## Corrections and evidence

| Finding | Correction | Regression evidence |
| --- | --- | --- |
| **F1 HIGH — false destination coverage after rebinding** | `TransactionalRepository.bind()` retains the last destination across disconnect. It rejects account/locator changes while any history, publication, accepted segment or known artifact reference remains. This covers acknowledged, received-only, tombstoned and unsealed corpus, rather than only active publication intents. A deliberate full-corpus transfer is still deferred; empty replicas can change destination. Same-target reconnection preserves known obligations and uses a fresh generation. | `test/sync-coverage-regressions.test.js`: direct and disconnect/reopen retarget attempts across five corpus modes; account and locator independently changed; full durable state unchanged on refusal; safe original-target resume; empty-replica control. |
| **F2 HIGH — own upload lost before first enumeration** | `AdversarialTransport.publish()` returns verified physical `references`. The confirmation transaction stores the original bytes, segment identity and locator obligations before acknowledgement, using the new `confirm.coverage` persistence boundary. Later passes check these known references even when enumeration omits them. References are unioned, never replaced. A confirmation without locators may acknowledge exact outbox membership but retains unresolved logical coverage and cannot produce Synced until discovery verifies that segment. `receive()` resolves that obligation atomically with its accepted effects. | `test/sync-coverage-regressions.test.js`: missing, malformed, unsupported, conflicting and oversized own uploads before their first listing; delayed listing/truncated reads; crashes after confirm/ack commits; confirmation conflict rollback; opaque prototype-looking locators; reference-free ack/reconnect/discovery; injected failure at coverage and applied markers. |
| **F3 MEDIUM — unintended received-description edits** | `edit()` first validates the complete snapshot, then checks the current base inside the transaction. It applies the authoring whitespace/default rule only when the description itself differs from the current value. Equal descriptions remain exact, including empty text, surrounding whitespace and normalization-distinct scalars. The complete resulting snapshot is compared for no-op before ID/counter/outbox allocation. | `test/snapshot-segment-regressions.test.js`: received empty, surrounding-whitespace, fixed-whitespace-only and decomposed Unicode values survive exact no-ops and separate duration/start/end edits; actual description changes still use authoring rules; a change that normalizes back to the current value is a no-op. |
| **F4 MEDIUM — reserved/accepted segment byte conflict** | `seal()` rechecks the accepted segment registry inside its transaction before persisting final bytes. A reservation recovered after a crash cannot seal a second byte value under an intervening accepted identity. The runner blocks on the integrity error before making a publication call. The converse sealed-first receive check remains in force. | `test/snapshot-segment-regressions.test.js`: crash after reservation commit, opposing remote segment, reopen/receive/seal; accepted bytes retained, local intent remains unsealed, outbox remains reserved, zero network publication attempts. The inverse ordering rejects receive with no partial effects. |
| **F5 LOW — unbounded standalone parser policy** | Standalone `parseSession`, `parseOperation` and generic `parseWireJson` now apply `DEFAULT_MAX_PARSE_BYTES` (1 MiB) before decoding/allocation. A caller can specify a byte budget or explicitly opt out with `Infinity`. Refusal throws `ResourceLimitError`, with no protocol classification. Descriptor/segment mandatory caps still reject as malformed and cannot be overridden. This adds application resource policy, not a new standalone wire-validity rule. | `test/standalone-resource-policy.test.js`: 10 cases cover exact budgets, early refusal before UTF-8 decoding, non-ASCII byte counts, configurable larger budgets, explicit opt-out, option validation, preserved wire classifications and non-overridable descriptor/segment caps. |
| **F6 LOW — arithmetic-only lifecycle fixture driver** | The existing four neutral Lamport sequences now run through `MemoryStore`/`TransactionalRepository`: actual segment receive, local active/Finish commands, reopen, distinct writer rotation and projection reconstruction through retained redelivery. Only the fixture's initial persisted high-water is seeded directly. No new production lifecycle API or vector values were invented. | `test/conformance.test.js`: each step asserts fixture-defined durable high-water; local counters, writer identity, domain/outbox state and exhaustion rollback are checked directly. Restart compares full retained state; rotation preserves the corpus; cache rebuild preserves operations/outbox and C. The same 245 conformance cases remain. |

## Test results

- `npm test`: **532/532 passed**, zero failed, skipped or cancelled.
- `npm run test:reference`: **31/31 passed**, rebuilt from unchanged reference source.
- The 24 coverage regressions, seven description/segment regressions and 10 standalone resource cases add 41 focused cases. The new confirmation boundary adds one crash-matrix subtest. The Lamport correction strengthens the existing four sequence cases without increasing their count.
- Initial targeted runs reproduced the review failures before the corresponding production corrections. Independent review of the corrected binding/confirmation/receive/status paths found no additional defect in those paths and added the confirmation-conflict, prototype-reference and commit-boundary checks.

The old stale-binding test setup rebound a nonempty collection to another target. It now obtains a fresh generation for the original target, preserving its stale-generation assertion and active-idle guard without depending on the unsafe transition being corrected.

## Guarantees and remaining boundary

The reproduced unsafe transitions now fail locally or remain explicitly unresolved; they do not claim coverage, rewrite unrelated fields or publish conflicting bytes. Exact-byte retries, operation-set reduction, terminal deletion, high-water rules and precise acknowledgement membership remain unchanged.

This is still an ideal serial in-memory transaction/transport model. Verified transport confirmations are assertions supplied by the model, not evidence that a real provider performs equivalent verification. Real persistence/isolation/durability, execution-lifetime fencing, actual clocks/suspension and provider authorization/availability require the later platform proof gates. No UI, production IndexedDB, Drive, OAuth, PWA or full corpus-transfer/adoption workflow was implemented as part of these corrections.
