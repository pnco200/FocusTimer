# Existing application behavior baseline

Baseline recorded on 2026-10-17 from the supplied **Studytime 1.2**, a C# / .NET Framework 4.8 WinForms application. This is observed reference behavior, not a prescription to retain its architecture. `SPEC.md` Draft v3 is authoritative for the portable implementation. No reference source files were changed.

Sources inspected: `Reference-FocusTimer-SourceCode/Core.cs`, `UI.cs`, `Program.cs`, `Tests.cs`, `README.txt`, `Verification.txt`, and `build.ps1`; compared against SPEC §§3–10, 27–29, and 33–37. No applicable `AGENTS.md` was present in the repository or its searched project parent.

## Initial verification

The original build and self-test were run before protocol production changes. `build.ps1` invokes the installed .NET Framework C# compiler with the original core, native UI, program, tests, icon, and manifest. The self-test uses isolated files beside its report, never the user's `%LOCALAPPDATA%\Studytime` records.

First attempt built and ran in the command sandbox's temporary directory: **27/31 passed**, executable exit **1**. Four tests failed with `UnauthorizedAccessException` at `File.InternalMove`: Unicode JSON persistence, corrupt-file backup recovery, pin preference persistence, and dark preference persistence. These failures were confined to creating the primary JSON file in that temporary environment.

Rebuilding and running the unchanged source with an explicit writable repository output/report directory resolved all four failures: **31/31 passed**, executable exit **0**. This establishes the passing initial baseline. Generated binaries, reports, and isolated test data belong under ignored `.artifacts/`, outside the reference source tree.

Reproducible PowerShell commands from the repository root:

```powershell
$baselineDirectory = Join-Path (Get-Location) '.artifacts\reference-baseline'
& .\Reference-FocusTimer-SourceCode\build.ps1 -OutputDirectory $baselineDirectory
$baselineReport = Join-Path $baselineDirectory 'results.txt'
$baselineProcess = Start-Process `
    -FilePath (Join-Path $baselineDirectory 'Studytime.exe') `
    -ArgumentList ('--self-test "' + $baselineReport + '"') `
    -WindowStyle Hidden -PassThru -Wait
$baselineProcess.ExitCode
Get-Content -LiteralPath $baselineReport
```

The supplied `Verification.txt` also records an earlier 31/31 pass; it is historical evidence, not the result substituted for this run. The current 31 checks cover timing/commands, finish/reset/close/recovery, failed writes, title bounds, deletion, formatting/CSV, JSON round-trip/recovery/ID validation, actual native controls/topmost/compact layouts, legacy preferences, and dark-mode persistence/readability/scrolling. They do not prove protocol conformance, real suspend behavior, browser durability, or multi-client convergence.

## Behavior and treatment

**PRESERVE** means preserve the user-visible semantics. **ADAPT FOR WEB** means preserve the goal while implementing SPEC's portable or platform-specific requirements. **REMOVE** means do not port the reference mechanism into the portable core or web client.

| Area | Observed behavior and evidence | Treatment under SPEC |
|---|---|---|
| Stopwatch | `StudyClock` exposes `Stopwatch.ElapsedMilliseconds`; focus is saved accumulation plus the current running monotonic interval. A 100 ms UI tick refreshes display; it does not measure duration by counting ticks. Display truncates to seconds and hours do not wrap after 24. Positive subsecond sessions are valid. | **PRESERVE** running-interval accumulation, millisecond history, subsecond completion, and nonwrapping hours. **ADAPT FOR WEB** the clock source and scheduling; prove background/suspend behavior. |
| Start/resume | Start from idle captures `UtcNow` once. Resume retains original start and accumulated focus. Start while running is a no-op. | **PRESERVE**. Add SPEC's local active identity, revision, transactional ownership, and fencing rather than sharing active state remotely. |
| Pause | Pause snapshots focus and clears running state. Repeated pause while paused/idle is a no-op. Paused time, including a long break before finishing, is excluded. | **PRESERVE**. |
| Finish | Running or paused positive focus creates one `StudySession` with a fresh `Guid`, original start, current UTC finish, and sampled focus. Only successful storage replaces active state with a new empty draft. Repeated finish after success throws in the engine; the UI ignores nonpositive focus and disables Finish. | **PRESERVE** positive duration and clear-after-success semantics. **ADAPT FOR WEB** duplicate/concurrent Finish to consume an expected active identity/revision atomically with the immutable operation/outbox, returning the existing outcome or a stale command instead of creating a duplicate. |
| Reset | Clears start/running/elapsed while preserving current title and all completed records. UI confirms only if positive focus exists, pauses before opening the dialog, and resumes on cancellation only if previously running. Confirmation time is excluded. Engine reset itself does not prompt. | **PRESERVE**. Reset creates no completed record or history operation. |
| Active descriptions | Active title is optional and editable. `SetTitle` immediately changes in-memory draft; UI checkpoints about 700 ms after the last change. Completion applies .NET `Trim()` and substitutes `Untitled session` (no period) for whitespace-only input. Input and engine limit title to 120 UTF-16 code units. | **ADAPT FOR WEB** to the exact fixed authoring whitespace set, **120 Unicode scalars**, and the authoritative SPEC §9 literal `Untitled session.` **including its period**. The default punctuation differs from the reference. Preserve received/imported text, including empty and normalization-distinct strings; do not trim during reduction. Unsaved keystrokes are not yet durable. |
| Completed descriptions/editing | Completed records have no edit command or editor. Only the active title can be changed; completed history can be deleted. | **ADAPT FOR WEB**: completed-session editing is a **new** SPEC requirement, covering description, start/end, and focus independently, with stale-base checks. Do not describe it as an existing feature. |
| Local persistence | Entire `AppData` v1 includes active draft/running checkpoint, completed history, topmost, and theme at `%LOCALAPPDATA%\Studytime\sessions.json`; replacing/moving the executable preserves records. State transitions/checkpoints save synchronously. | **PRESERVE** local use without account/network and truthful durable success. **ADAPT FOR WEB** to transactional persistence. **REMOVE** the full AppData file/Windows path/serializer as a synchronization format. Only completed FocusSession operations synchronize. |
| Orderly close/reopen | `Close()` saves a paused snapshot. Constructor always forces loaded active work paused, even if the stored checkpoint says Running. Original start/title/accumulation survive. No closed/offline time is added. Restore notice invites Resume. | **PRESERVE** paused recovery when the execution owner is gone. **ADAPT FOR WEB** close handlers to best effort, and attach to a surviving live tab owner instead of pausing it. |
| Crash/restart | While running, UI attempts a checkpoint after roughly five seconds since the prior save; reload restores the last successful accumulation paused. Checkpoint anchoring is captured before disk I/O so save latency remains part of a surviving running interval. | **PRESERVE** recovery and latency continuity. **REMOVE** the README's implication that crash loss is always at most five seconds: throttling, failed storage, or unavailable execution may make the window longer. |
| Save errors | Engine builds a snapshot, saves it, then updates current in-memory state. Failed Finish preserves active work and adds no history; failed Pause/Reset/preferences preserve previous state. UI reports a save error. A title draft is already in memory before its later checkpoint. | **PRESERVE** failure visibility and no false completion/reset. **ADAPT FOR WEB** atomically commit domain state, immutable operation, Lamport high-water, and exact outbox membership; in-memory drafts are distinct from durable success. |
| Autosave/close failure | Failed autosave keeps work in memory, warns to keep the app open, and delays retries (the code moves save/title deadlines forward by about 30 seconds). Failed close initially cancels closing, then explicitly offers closing without the latest save. | **PRESERVE** a visible durability error and recovery from the last committed checkpoint. **ADAPT FOR WEB** retry scheduling/notices and shutdown limits; no promise that close callbacks run. The exact retry delay is native policy, not protocol semantics. |
| Completed history | Completed records only; newest `FinishedUtc` text first, finish date/time/title/focus displayed, three recent rows where layout fits. Search trims the query and uses current-culture case-insensitive substring matching. Search does not affect stored history. | **PRESERVE** finished-only local projection, search, recent entries. **ADAPT FOR WEB** canonical UTC millisecond dates and SPEC's entity-ID ascending tie-break for equal finish timestamps, which the reference does not define. Search collation is presentation-only. |
| Delete | Confirmed UI deletion removes matching ID from the saved list, preserving all others. Unknown ID is a no-op. There is no undo/tombstone or remote synchronization. Deleting while running snapshots active focus as part of saving. | **PRESERVE** confirmation and unrelated history. **ADAPT FOR WEB** to terminal DELETE facts retained indefinitely; repeated tombstoned/unknown local deletion is a no-op. Restore/copy uses a fresh entity ID. |
| Statistics | Today, Monday-through-today, and all-time sum completed `DurationMs` and count records. The entire duration belongs to the finish date in the viewer's current local timezone. Active focus is excluded. All-time includes future-dated records. Display rounds down to whole minutes, with `< 1 min` for positive shorter totals. | **PRESERVE** attribution, filters, counts, and exclusion of active work. **ADAPT FOR WEB** exact checked aggregation and responsive display. No pause/day splitting can be inferred from these records. |
| CSV export | Exports **all** finished history, regardless of search. Rows sort newest finish first. Columns: Title, Started (local), Finished (local), Effective time, Effective seconds. Text cells are quoted and quotes doubled; formula-leading `= + - @ TAB CR LF` receives a leading apostrophe. Seconds retain three decimals. Export uses UTF-8 BOM; errors are shown. | **PRESERVE** reporting behavior and formula protection. **ADAPT FOR WEB** download/share interaction and portable labels. CSV is not an identity-preserving backup or required import format. SPEC's history JSON/archive are additional formats. |
| System sleep | README claims minimized or sleeping running time counts. Code has no suspend/resume handler; it relies solely on platform `Stopwatch`. Manual-clock tests prove injected elapsed accumulation, not actual physical system sleep continuity. | **ADAPT FOR WEB**: intended running sleep continuity requires runtime proof under SPEC §6. Where reliable measurement is unavailable, preserve last proven durable focus, recover paused, and disclose possible missing time. Never silently infer arbitrary wall-clock gaps. |
| Single instance | A named Windows mutex prevents a second application instance; the program attempts to focus the existing window. | **REMOVE** native mutex/process/window plumbing from the core. **ADAPT FOR WEB** the one-active-local-stopwatch goal with execution-lifetime ownership and transactional fencing. Independent installations may run independently. |
| Theme/layout/shortcuts | Persistent light/dark and topmost preferences; responsive compact native layout hides totals/recent rows while retaining timer/history controls. Native shortcuts include Space outside inputs, Ctrl+Enter/Reset/history/timer, and theme/topmost toggles. Controls expose accessible names and keyboard focus; theme tests cover contrast. | **ADAPT FOR WEB** layout, light/dark, semantic accessible controls, notices, and safe shortcuts. Preferences remain local. **REMOVE** mandatory topmost, native DWM/user32 drawing/scrollbar APIs, and browser-reserved shortcut interception. |

## Storage and import nuances

`JsonStateStore.Save` validates before writing, writes a unique temporary sibling, flushes to disk, then uses `File.Replace` with `.bak` for an existing primary. On first save it creates the initial backup before moving the primary so an error after the primary commit cannot cause a successful operation to be retried. Temporary siblings are deleted in `finally`. This is the reference's local file mechanism; it does not establish the transactional multi-store invariants needed for protocol operations.

On load, a missing primary with a backup loads the backup. An unreadable primary with a valid backup copies the damaged primary to `.corrupt-<timestamp>` and restores the backup; the first post-recovery save preserves that backup. If both sources are invalid or a primary is unreadable without a backup, load fails visibly and retains evidence. Missing both files is the only ordinary new empty state. Preserve these recovery principles; do not synchronize physical file absence as deletion.

Reference validation accepts only AppData Version 1 and non-null current/list, nonnegative active accumulation and positive completed duration bounded by 3,155,760,000,000 ms. Completed titles must be nonblank and at most 120 UTF-16 units. It uses permissive `Guid.TryParse`, compares duplicate IDs as strings, and parses .NET round-trip timestamps through `DateTime.Parse`; it does not implement strict portable UUID, scalar, number-token, closed-shape, or calendar wire validation. New protocol validation must not inherit that permissiveness. Legacy import under SPEC §29 preserves supported UUID identities after canonicalization, detects canonical collisions, converts supported date instants to UTC millisecond precision, preserves duration/text, and quarantines unsupported records. It must not invent focus from wall-clock span or synchronize active state/preferences.

No reference behavior requires a countdown, target duration, automatic completion, account, telemetry, network, completed-session editing architecture, or Google integration. This task implements portable protocol proof only; the web UI, real persistence, suspend/ownership integration proof, and provider authorization remain later phases.
